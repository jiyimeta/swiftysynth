forever); fixture-dependent tests reference it at an absolute path and skip
when it is absent.

## `generaluser-gs-dump.json` (Task 4 — G1 loader-equivalence vector)

Generated by `oracle dump-font <sf2> <out.json>` (`Tools/oracle/src/main.rs`).
Its JSON key names are the normative contract `OracleDump.swift` (Task 14)
mirrors — see the schema documented in `.superpowers/sdd/task-4-brief.md`.

- Serialized with `serde_json::to_string` (compact), **not**
  `to_string_pretty`. The pretty form was 2.2 MB; switching to compact
  brought it to ~1.7 MB (1056 `bank0Preset0.pairs` records × ~44 fields
  each dominates the size — `pairs` alone is ~1.4 MB even compact).
- The file is still slightly over the ~1.5 MB soft target noted in the
  Task 4 brief even after the pretty→compact switch. No further
  compaction was applied: shortening key names or truncating float
  precision would break the schema's normative contract (exact camelCase
  keys; float fields are the *exact* f32-widened-to-f64 value, not a
  re-rounded approximation — `serde_json`'s f64 serializer already prints
  the shortest decimal that round-trips to that exact bit pattern, so
  these numbers cannot get shorter without changing the value). Dropping
  fields from `pairs` was explicitly out of scope (G1-critical). Flagged
  as a concern in the Task 4 report rather than resolved unilaterally.

## Regeneration (manual — tests never invoke the oracle)

```sh
cargo build --release --manifest-path Tools/oracle/Cargo.toml
Tools/oracle/target/release/oracle dump-font "<sf2-path>" Tests/SwiftySynthTests/Fixtures/generaluser-gs-dump.json
Tools/oracle/target/release/oracle render-note "<sf2-path>" Tests/SwiftySynthTests/Fixtures/note-c4-vel100.wav Tests/SwiftySynthTests/Fixtures/note-c4-vel100.json
```

The fixture note: bank 0 / preset 0, key 60 (C4), velocity 100, 44.1 kHz stereo,
noteOn at frame 0, noteOff at frame 88200 (rendered as two chunks: 88200 then 132300
frames), 220500 frames total, master volume 0.5, block size 64, dry (no reverb/chorus).
