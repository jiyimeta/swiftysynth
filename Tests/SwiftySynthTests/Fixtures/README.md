# Test fixtures

Committed, derived test vectors for the spike gates. The 32 MB GeneralUser GS
font itself is NOT committed (it would bloat every SwiftPM consumer's clone
forever); fixture-dependent tests reference it at an absolute path and skip
when it is absent.

## `generaluser-gs-dump.json` (Task 4 — G1 loader-equivalence vector)

Generated by `oracle dump-font <sf2> <out.json>` (`Tools/oracle/src/main.rs`).
Its JSON key names are the normative contract `OracleDump.swift` (Task 14)
mirrors — see the schema documented in `.superpowers/sdd/task-4-brief.md`.

- Serialized with `serde_json::to_string` (compact), **not**
  `to_string_pretty`. The pretty form was 2.2 MB; switching to compact
  brought it to ~1.7 MB (1056 `bank0Preset0.pairs` records × ~44 fields
  each dominates the size — `pairs` alone is ~1.4 MB even compact).
- The file is still slightly over the ~1.5 MB soft target noted in the
  Task 4 brief even after the pretty→compact switch. No further
  compaction was applied: shortening key names or truncating float
  precision would break the schema's normative contract (exact camelCase
  keys; float fields are the *exact* f32-widened-to-f64 value, not a
  re-rounded approximation — `serde_json`'s f64 serializer already prints
  the shortest decimal that round-trips to that exact bit pattern, so
  these numbers cannot get shorter without changing the value). Dropping
  fields from `pairs` was explicitly out of scope (G1-critical). Flagged
  as a concern in the Task 4 report rather than resolved unilaterally.

## `multi-gm-dry.wav` / `multi-gm-dry.json` (G2-multi vector)

Generated by `oracle render-multi <sf2> <out.wav> <out.json>`
(`Tools/oracle/src/main.rs`, `MULTI_MESSAGES`). 5.0 s (220500 frames),
44.1 kHz float32 stereo, block 64, polyphony 64, dry (effects off), master
volume 0.5. Exercises program change, CC channel volume / pan / expression
(incl. mid-note), RPN pitch-bend-range + pitch bend, and percussion channel 9.

The sidecar's `messages` array is normative twice over: it is the event
stream AND the shared chunk-boundary list — the oracle and the Swift G2-multi
test both render exactly the frame spans between consecutive message frames,
so the internal 64-frame block phase matches on both sides.

Stream constraints (Channel-model divergence): no NRPN (CC 0x62/0x63); data
entry (0x06/0x26) always preceded by an RPN select (0x65/0x64). rustysynth
gates data entry on an RPN/NRPN flag that canonical C# MeltySynth (and
therefore this port) does not have; under these constraints both dispatch
identically.

## `multi-gm-fx.wav` / `multi-gm-fx.json` (G2-fx effects-on vector)

Generated by `oracle render-fx <sf2> <out.wav> <out.json>`
(`Tools/oracle/src/main.rs`, `FX_MESSAGES`). 5.0 s (220500 frames), 44.1 kHz
float32 stereo, block 64, polyphony 64, **reverb + chorus ON**, master
volume 0.5. Effects-focused coverage: the 40/127 channel-default reverb
send, explicit reverb-send changes (incl. mid-note ramps), chorus enabled
via CC 0x5D (off by channel default) from frame 0 / raised mid-note /
switched on mid-note, percussion through the reverb bus including a crash
cymbal (on at frame 108045, off at frame 127890) whose bright reverb/chorus
decay rings on into the tail, and a final GENUINE ~2 s pure tail: the LAST
message of any kind (a note-off) lands at frame 132300, so frames
132300–220500 carry ZERO note-on/off/CC events — the tail there is fed only
by decaying reverb/chorus state (the feedback-drift region the calibrated
G2-fx tolerance is measured on). The crash is deliberately placed BEFORE
frame 132300 rather than mid-tail (as an earlier draft of this vector had
it) so it enriches that decaying state instead of injecting fresh energy
into the drift-calibration window.

Same dual-normative `messages` convention as `multi-gm-dry`: the event
stream AND the shared chunk-boundary list. Same stream constraints (no
NRPN; additionally NO data-entry messages at all).

Component-level reverb/chorus vectors deliberately do NOT exist: rustysynth
1.3.6's `Reverb`/`Chorus` are `pub(crate)` (P0 probe finding), and the
locked G2-fx strategy pins component correctness with hand-derived unit
tests (`ReverbTests`, `ChorusTests`) instead of a vendored/patched oracle.

## `midi-gm-song.mid` + `midi-gm-dump-*.json` + `midi-gm-seq.{wav,json}` (G-midi vectors)

`midi-gm-song.mid` is generated by `oracle make-midi <out.mid>` —
deterministic, byte-identical on every run (SHA-256 recorded below). SMF
format 1, resolution 480, 4 tracks, ~4.6 s: tempo 120→150 bpm at tick 1920,
program changes, running status (incl. vel-0 note-offs), CC volume/pan, RPN
pitch-bend-range + bends, percussion (ch9), SysEx + text-meta discards,
4 junk bytes after track 3's EOT (the skip case), and FinalFantasy loop
markers (CC116 @ t=1.0 s, CC117 @ t=4.4 s). The ch1 strings note-off sits
AFTER the loop end (t=4.6 s) so the loop rewind's note_off_all is exercised
in PCM. Stream constraints: no NRPN; the one data entry is RPN-selected.

- `midi-gm-song.mid` SHA-256: `dcf8008a16a43addcc39c92e76b90346ae922dda64662c6c27b6b47c6ffbc3b7`

`midi-gm-dump-{none,ff}.json` are `oracle dump-midi <mid> <looptype>
<out.json>` — the merged message list + EXACT f64 times, obtained via the
derived-Debug tap (rustysynth's MidiFile fields are pub(crate); the Debug
impl is public surface, frozen by the =1.3.6 pin; dump-midi self-checks the
tap against get_length()). 37 messages in both variants; the ff variant has
LoopStart at index 17 and LoopEnd at index 33 where the none variant has
the raw CC116/CC117 messages.

`midi-gm-seq.{wav,json}` are `oracle render-midi <sf2> <mid> <out.wav>
<out.json>` — the rustysynth MidiFileSequencer rendering the song with
loopType FinalFantasy, loop ON, 5.0 s (220500 frames): one full pass, the
loop rewind at ≈4.4 s (frame 194048) incl. the rewind note_off_all on the
still-held strings note, then the replayed loop region. Settings: 44.1 kHz,
block 64, polyphony 64, EFFECTS ON, master 0.5, speed 1.0. Rendered in ONE
call — the sequencer owns the block walk, so caller chunking cannot move
events (the Swift gate renders 997-frame chunks to assert that).
